# Reflect

## 1. สแกน session นี้
หา:
- ผู้ใช้แก้หรือค้านอะไร
- tool/สคริปต์พัง แล้วต้องหาทางอ้อม (workaround)
- สมมติฐานที่ผิด (เช่น path, รูปแบบไฟล์, ชื่อหุ้น)
- งานที่ทำซ้ำหลายรอบกว่าจะถูก
- ความชอบ/วิธีทำงานของผู้ใช้ที่เพิ่งรู้

ข้าม: เรื่องเล็กที่ไม่น่าเกิดอีก, สิ่งที่บันทึกไว้แล้ว (เช็ค `MEMORY.md`, `CLAUDE.md`, `guides/`).

## 2. ส่งแต่ละบทเรียนไปที่ที่ "บังคับ" ได้จริง (`guides/principles.md` §1)

ถามทีละข้อ ตามลำดับ — หยุดที่ข้อแรกที่ใช่:

| ลำดับ | ถ้า… | ทำ |
|---|---|---|
| 1 | แก้สคริปต์/tool ให้ทำถูกเองได้ | แก้โค้ด (เช่น ใส่ `exif_transpose`, fallback ffmpeg) |
| 2 | เป็นขั้นตอนของงานประเภทหนึ่ง | แก้ skill หรือ agent ที่ทำงานนั้น (`.claude/skills/`, `.claude/agents/`, `.claude/commands/`) |
| 3 | ต้องเกิดอัตโนมัติตามเหตุการณ์ | เสนอ hook (ใช้ skill `update-config`) |
| 4 | ใช้ได้ข้ามงาน เกี่ยวกับตัวผู้ใช้/วิธีทำงาน | memory (`feedback_*` / `user_*`) ตาม format ใน system prompt |
| 5 | หลักคิดที่ใช้กับทุกงาน | เสนอเพิ่มใน `guides/principles.md` (ถามผู้ใช้ก่อน) |

**ห้าม** จดเป็น memory ถ้าข้อ 1–3 ทำได้ — คำสั่งที่เป็นตัวหนังสือถูกลืมได้, โค้ดไม่ลืม.

## 3. ลงมือ
- ข้อ 1–2 ที่แก้ไฟล์เล็ก ชัดเจน → ทำเลย
- แก้ใหญ่ / เปลี่ยน logic / hook / principle → สรุปให้ผู้ใช้อนุมัติก่อน (กฎ "วางแผนก่อนลงมือ")
- งานยาวที่ต้องให้ Sonnet ทำ → เพิ่ม task ใน `for-sonnet/tasks.md`

## 4. รายงานสั้นๆ
ตาราง: **บทเรียน | ไปที่ไหน | ทำแล้ว/รออนุมัติ**. ไม่มีอะไรน่าบันทึก → บอกว่า "ไม่มี" ได้.

# Meditate

เกณฑ์: memory หนึ่งข้อ "มีค่าพอจะอยู่" เมื่อ **ถ้าไม่มีแล้ว Claude จะทำผิดแน่ๆ** หรือ **ใช้บ่อย** หรือ **พลาดแล้วเสียหายมาก**. นอกนั้นคือภาระ context ทุก session.

## 1. รวบรวม
- `~/.claude/projects/-Users-alonsi-Desktop-studio/memory/` (MEMORY.md + ทุกไฟล์)
- `CLAUDE.md`, `guides/*.md`
- รายชื่อ skills/agents/commands (`ls .claude/skills .claude/agents .claude/commands`) — อ่านเฉพาะที่ memory อ้างถึง

## 2. ตรวจทีละไฟล์ memory
| ปัญหา | วิธีเช็ค | ทำ |
|---|---|---|
| **เก่า/จบแล้ว** | โปรเจกต์เลิก, pending ที่ทำเสร็จแล้ว, อ้างไฟล์/คำสั่งที่ไม่มีแล้ว (`ls`/`grep` ยืนยัน) | ลบ |
| **ซ้ำ** | 2 ไฟล์พูดเรื่องเดียว หรือซ้ำกับ CLAUDE.md/guides | รวมเป็นไฟล์เดียว |
| **ขัดกัน** | memory บอกอย่าง, CLAUDE.md/skill บอกอีกอย่าง | ถามผู้ใช้ว่าอันไหนถูก |
| **ควรเป็นโครงสร้าง** | เป็นขั้นตอนเฉพาะงาน (เช่น flag ของ yt-dlp) | ย้ายไปไว้ใน skill/สคริปต์นั้น แล้วลบ memory |
| **ยาวเกิน** | เกิน ~15 บรรทัด หรือเล่าเรื่องแทนที่จะบอกกฎ | ย่อให้เหลือ: กฎ + Why + How to apply |

แล้วตรวจ `MEMORY.md`: ทุกบรรทัดชี้ไฟล์ที่มีจริง, ทุกไฟล์มีบรรทัดใน index, คำอธิบายสั้นพอให้ตัดสินใจว่าจะเปิดอ่านไหม.

## 3. มองภาพรวม
- บทเรียนหลายข้อชี้ไปทางเดียวกัน → เสนอเป็น principle ใน `guides/principles.md`
- CLAUDE.md ยาวขึ้นเรื่อยๆ → เสนอย้ายรายละเอียดไป `guides/` (CLAUDE.md เป็นแค่ router)

## 4. เสนอผู้ใช้ก่อนลงมือ
ตาราง: **ไฟล์ | ปัญหา | เสนอให้ทำ (ลบ/รวม/ย้าย/ย่อ)**.
การลบหรือเขียน principle ใหม่ → ต้องได้รับอนุมัติก่อนเสมอ. แก้คำผิด/ลิงก์เสียใน index → ทำได้เลย.
